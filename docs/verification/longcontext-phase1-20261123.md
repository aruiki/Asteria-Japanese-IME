# 長い前の文を AI へ届ける(Phase 1、2026-11-23)

カード 94。Gemini の診断(利用者が共有した改善ロードマップ)の Phase 1 のうち、1-1(TSF の前の文の取得長)と
1-3(モデル別の文脈長)。

## 変更

- TSF: カーソルの前の文を 20 → 256 文字取る(REQ-10-2 の値)。後ろの文は 20 文字のまま。Mozc 本体の前の文の
  使い方(履歴の作り直し・予測の学習・数字の履歴)はどれも末尾だけを見るので結果は変わらない。
- 変換器: 文全体の候補を LLM(TinySwallow・判定役)で採点するときだけ、前の文を末尾 240 → 768 バイト(約 256 文字)渡す。
  genmai の生成・採点は 40 → 120 文字。覚えた結果の鍵・文脈の学習の照合・繰り返し癖の判定・打ち間違いの補正は
  従来の長さのまま(遠くの語での誤発火を増やさない)。

## 評価セット

`eval/sets/asteria-longcontext-dev-20261123.json`(52 問、`eval/sets/make_longcontext.py` で生成。開発用)。
話題を決める手がかりの文の後ろに、話題に中立な 85 文字以上の文を挟む。同じ読みに別の意味の手がかりを付けた組を含む。

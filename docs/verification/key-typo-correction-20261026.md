# 打ち間違いの補正(キーの単位・複数か所)と「たまに外れる」の点検(v3.1.0、2026-10-26〜27)

[ADR0074](../adr/0074-key-level-typo-correction.md) の検証記録。

## 条件

- 製品と同じセッションの経路: `mozc/tools/session_eval.py`(`session_handler_main` を 1 プロセスで起動し、ローマ字を
  打って Space、AI の結果が届くまで待って 1 番目の候補を取り、Esc で取り消す。確定しないので学習しない)。
  打ち間違いの 5 例は、打ったキーをそのまま送る(`"romaji"`。かなから組み立て直すと間違いが消えるため)。
- RTX 3060(Vulkan)、Standard、モデルは v3.0.0 と同じ(zenz-v2.5-small、TinySwallow-1.5B)。
- 比べたもの: **v300** = v3.0.0 と同じ動き(`KOTORI_LM_TYPO_KEYS=0 KOTORI_LM_TYPO_WAIT_MS=0`)、
  **v310** = 今回の既定。同じバイナリで環境変数だけを変えた。
- Space を押すタイミング: **既定** = 入力中の取り直しを待って押す(手を止めてから押す)、**すぐ** = 打ち終わってすぐ、
  **0.15 秒** = 最後の打鍵から 0.15 秒後。
- Mozc の作業ツリー `~/ag16`(v3.0.0 のソース 4d5fe280a から)。原票は `target/accuracy-guide/v310-final/`。

## 正解数

| 評価セット | 既定 v300 → v310 | すぐ v300 → v310 | 0.15 秒 v300 → v310 |
| --- | --- | --- | --- |
| 利用者の打ち間違い 5 例 | 0 → **3** | 0 → 0 | 0 → 0 |
| 打ち間違い(kotori-typo、40) | 17 → **24** | 4 → **16** | 4 → **15** |
| 日常(kotori-daily、81) | 79 → 79 | 79 → 79 | 79 → 79 |
| 短文(asteria-short-dev、120) | 118 → 118 | 118 → 118 | 118 → 118 |
| 同音語(kotori-homophone、40) | 38 → 38 | 38 → 38 | 38 → 38 |
| AJIMEE(前文あり、198) | 187 → 187 | — | — |

v300 で正しかった文が v310 で外れたものは、全セット・全タイミングで **0**。v310 で新しく正しくなった文は 33。

5 例で直せたのは、抽出・失礼・続き(手を止めてから Space)。お迎えは 2 秒手を止めると直る。今日学校に… は、
「がっく(学区)」が実在の語で辞書でも LLM でも見分けにくく、さらに「と」の抜けがあり、直せない。すぐ Space を
押したときの軽い補正は、かなの 1 か所の書き換えだけなので、キーの単位の打ち間違い(5 例の多く)は直らない。

## Space の待ち(Space から候補が出るまで、p95)

| 評価セット | 既定 v300 → v310 | すぐ v300 → v310 | 0.15 秒 v300 → v310 |
| --- | --- | --- | --- |
| 打ち間違い(40) | 2 → 18 ms | 119 → 233 ms | 35 → 135 ms |
| 日常(81) | 2 → 2 ms | 140 → 139 ms | 36 → 50 ms |
| 短文(120) | 2 → 2 ms | 89 → 113 ms | 34 → 65 ms |
| 同音語(40) | 3 → 3 ms | 135 → 142 ms | 36 → 37 ms |
| AJIMEE | 40 → 39 ms | — | — |

打ち間違いのある文は、すぐ Space を押したときに軽い補正をする分だけ待ちが延びる(その代わり 4 → 16 問直る)。
関所を通るふつうの文でも、短文の 0.15 秒で p95 が 34 → 65 ms に延びた。精度と「たまに外れる」をなくすことを
優先した(利用者の指示)。

変換器を直接呼ぶ経路の Space(`mozc/tools/space_latency.py`、0.15 秒間隔で打つ)は、日常 p95 136 → 137 ms、
打ち間違い 225 → 218 ms。

## v3.1.0 の準備中に見つけて直した不具合

1. **その場の変換で深い探索が Space を待たせる**: 変換器を直接呼ぶ経路で、キーの単位・複数か所の探索が Space の
   後に走り、日常の文の Space の p95 が 139 → 430 ms になった。探索は手が止まった間の裏の仕事でだけ行うように
   した。直した後 136 → 137 ms。
2. **すぐ Space を押すと打ち間違いが直らない(v3.0.0 から)**: Space を待っている間の補正をすべて省いていたため、
   打ち間違い 40 問はすぐ押すと 4 問、手を止めると 17 問(v3.0.0)と、タイミングで結果が変わった。打ち直すと
   直る「たまに外れる」の原因の 1 つ。Space の後も軽い補正を 200 ms まで行うようにした(4 → 16 問)。
3. **自然な文を別の語に変える(開発中に見つけ、出荷前に直した)**: キーの書き換えまで含めて関所を判定すると、
   また今度遊ぼう → 街コンで遊ぼう、請求書 → 京急小、納品書 → 脳筋性、息が合う → 息がある、と直してしまった。
   関所はかなの 1 か所の書き換えだけで判定し、点の差の基準を緩めるのは ず/づ・じ/ぢ の書き分けだけにした。
4. **時間切れで見つけた直しを捨てる**: 2 か所目以降を探している途中で時間が切れると、1 か所目の直しも捨てていた
   (今日はいい天気でうね)。探し始めて 200 ms を過ぎたら次へ進まず、見つけた直しで文を作るようにした。

## タイミングで結果が揺れる文の点検

日常・短文・同音語・打ち間違い・5 例を、既定 2 回・すぐ・0.15 秒の 4 通りで変換し、1 番目の候補が変わる文を
数えた(`flaky-v1/keys1`)。打ち間違い以外で揺れたのは 1 文だけ(くーばねてぃす、どのタイミングでも不正解)。
打ち間違いの揺れは上の 2 の原因で、直した後は上の表のとおり。

## AI を通すとかえって外れる文の点検

AI を切った Mozc だけの結果(`--config kotori_lm_enabled=false`)と、v310 の既定を 1 問ずつ比べた。

| 評価セット | Mozc だけ | v310 |
| --- | ---: | ---: |
| 打ち間違い(40) | 4 | 24 |
| 日常(81) | 69 | 79 |
| 短文(120) | 113 | 118 |
| 同音語(40) | 29 | 38 |
| AJIMEE(198) | 106 | 187 |

Mozc だけなら正しく、AI を通すと外れたのは 4 文。どれも v3.0.0 でも同じ結果で、今回の変更によるものではない。
AI の採点の好みによるもので、無理に曲げるとほかの文を悪くするおそれがあるため、v3.1.0 では直さず記録する。

| 読み | Mozc だけ | AI を通す |
| --- | --- | --- |
| あついほん | 厚い本 | 熱い本 |
| たいじゅうをはかる | 体重を量る | 体重を測る(どちらも使う表記) |
| …ぞくへんをかくことを… | 続編を書く | 続編を描く |
| うかがえる | うかがえる | 伺える |

GPU がない設定(`KOTORI_LM_DEVICE=cpu`)でも、日常 79 / 81 で GPU と同じ。

`mozc/tools/stress_test.py`(1〜300 文字、記号・英数字・絵文字の読みで、入力中の候補・変換・Tab を交互に送る)を
v300 と v310 で、GPU と CPU(`KOTORI_LM_DEVICE=cpu`)の両方で実行し、4 つとも異常終了なし。

`//rewriter:lm_rewriter_test`(打ったキーの読み、5 例の書き換えの候補、元の読みを候補にしない・読みと合わない

## 受け入れた不足

- 5 例のうち直せるのは 3 例(手を止めてから Space)。すぐ Space を押したときは 0 例。
- 打ち間違いのある文では Space の待ちが延びる(上の表)。

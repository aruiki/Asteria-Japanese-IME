# 入力モードをアプリ・入力欄をまたいで保つ(2026-11-10)

カード 84 の続き。利用者の依頼:「ソフトをまたいだときの入力欄で必ず英字になるリセットをやめてほしい。
入力欄にフォーカスがなくても常に維持してほしい」。

## 症状と原因

- 実機(Asteria 3.34.6493.100、2026-11-10 導入)で、TSF のグローバル compartment に置いた全体の値を外から
  読むと `open=0 mode=0x9`(オフ、変換モードはひらがな)のまま固まっていた。アプリを切り替えるたびに TIP が
  この「オフ」を当てはめるため、どのアプリでも英字(直接入力)で始まっていた。
- 全体の値を書く条件が「このスレッドがキーボードを受けていて、キー操作から 1 秒以内に起きた変化」だった。
  Alt+Tab で移ると、移った先のスレッドは Alt を離すキーを受ける。その直後に OS(IMM32 の入力コンテキスト)や
  アプリが新しい窓・欄の既定値でオフにすると、それが利用者の選択として全体に書かれていた。
- 全体の値を当てはめるのは、TIP の起動とスレッドのフォーカスの変化だけだった。同じアプリの中で入力欄を移り、
  新しい欄の入力コンテキストの既定値(オフ)にされると、そのまま英字になっていた。
- サーバー(`session/`)は、新しいセッションをキーに付いたオン/オフと変換モードで始める(`HandleIndirectImeOnOff`)。
  サーバー側で英字に戻す処理はない。

## 変更

- 全体の値に書くのは、TIP 自身が利用者の操作(キー・言語バー・タスクバーの「あ/A」)を受けて書いた変化だけ。
  TIP が書いた値はスレッドごとに記録し、compartment の変化がその値と一致するかで見分ける。OS やアプリが書いた
  変化、入力欄の種類(パスワード・URL・数字など)で上書きされた状態、パスワード欄での変化は書かない。
- 全体の値を当てはめる時を、TIP の起動・スレッドのフォーカスに加えて、同じスレッドの中の入力欄の移動
  (`ITfThreadMgrEventSink::OnSetFocus`)にも広げた。
- フォーカスが変わってから 2 秒以内に OS やアプリがモードを変えたら、メッセージループに戻ってから全体の値に
  戻す(1 回のフォーカスで 3 回まで。アプリと戻し合いにならないように)。パスワード欄では戻さず、OS に任せる。
  欄を離れて次のフォーカスが来たときに全体の値に戻る。
- 全体の値の GUID を変えた。更新前の DLL がまだ読み込まれているアプリが書く値(固まった「オフ」を含む)を
  読まない。更新後、最初に利用者が切り替えたモードから共有が始まる。
- 設定「入力モードをすべてのアプリで共有する」(`kotori_share_input_mode`、既定オン)はそのまま。オフにすると
  Mozc と同じくスレッドごとのモードになる。

## 確かめたこと

- 単体テスト `//win32/tip:tip_shared_input_mode_test`(新規。書く・戻す・戻さない条件と値の形式)、
  `//session:session_test` の `KotoriNewSessionStartsInSharedInputMode`(新しいセッションが渡されたモードで始まる)。
  CI の「テストする」の一覧に TIP の 2 つのテストを足した。
- 実機での確認(メモ帳 → ブラウザ → エクスプローラーの検索欄)は、MSI を導入してから追記する。

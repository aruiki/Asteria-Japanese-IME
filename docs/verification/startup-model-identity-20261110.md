# 起動時のモデル全体のハッシュをやめる(2026-11-10)

利用者の指摘「必要以上に重量級で、変換速度や起動速度が最適化されていない」への 1 つ目の対策。

## 原因
非同期の読み込み(製品の既定)では、zenz(genmai)・TinySwallow・長い読み用の zenz を読み込む前に、
`KotoriModelIdentity` が毎回の起動でファイル全体の SHA-256 を計算していた(約 1.4 GB)。この値の用途は、
同じプロセスの中で「自由生成補正の結果が同じモデルから出たか」を比べることだけ
([2026-10-09-llm-model-identity](2026-10-09-llm-model-identity.md))。モデルの読み込みでもう一度ファイルを
読むため、ディスクのキャッシュがない起動では読み込みが二重になっていた。

## 変更
識別は、読み取りだけを共有して開いたハンドルから取る「ボリューム + ファイル ID(NTFS は 128 ビット)+
大きさ + 最終更新時刻」のキーにした。ハンドルを持つ間は書き換え・削除・名前の変更を Windows が拒否する
(従来どおり)。手放した後に書き換えれば更新時刻が、置き換えればファイル ID が変わるので、比べる目的には
同じ保証になる。中身を読まないので、起動での追加の読み込みはない。

## 測定
この PC(RTX 3060 12 GB、Standard、`converter_main` を製品と同じ裏読み込みで起動、日常 40 文)。
同じ時刻に旧(main + #213)・新を交互に 3 回ずつ。AI の準備完了は `kotori_ai_status.txt` が `state=llm` に
なるまでの起動からの時間。

| 回 | 旧: 準備完了 | 新: 準備完了 | 旧: 変換 中央値 / p95 | 新: 変換 中央値 / p95 |
| --- | ---: | ---: | --- | --- |
| 1(キャッシュなし) | 10,587 ms | 3,875 ms | 175 / 252 ms | 170 / 236 ms |
| 2 | 1,777 ms | 894 ms | 168 / 241 ms | 170 / 234 ms |
| 3 | 1,690 ms | 914 ms | 167 / 233 ms | 173 / 236 ms |

- 準備完了は温まった状態で約 0.8 秒(約 47%)短く、キャッシュがない最初の起動で約 6.7 秒短い。
  1 回目は旧から測ったので、新の 1 回目にはキャッシュの効果が一部ある。再起動直後の比較はしていない。
- 変換の時間・メモリ(約 3.0 GB)・VRAM(約 2.3 GB)は変わらない(変換の速さは次の作業)。

## テスト
`//rewriter:kotori_model_identity_test`(同じファイルで同じキー、同じ中身の別ファイルで別のキー、
同じ大きさの書き換え・置き換えで別のキー、所有中の書き換え・削除・名前変更の拒否、書き込み中のファイルの拒否、
日本語のパス)と `//rewriter:lm_rewriter_test` が成功。

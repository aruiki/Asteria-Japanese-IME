ライブ変換(ADR0077)、内蔵 GPU(ADR0078、試験的)、同音語のヒント(ADR0079)。手元は RTX 3060、Standard。

  `engine_converter_test` の `KotoriLiveConversion*`(オン・オフ、打ち足し、カーソル、確定の値と読み、読みを消したとき、

## 新機能オフのとき(既定の挙動が変わらないこと)

`regression_matrix.py`(全セット × 3 タイミング + 利用者の報告 + AJIMEE)で PR #201 の原票(`today-bayes2`)と比べた。
日常・短文・同音語・打ち間違いのキー 5 例・利用者の報告・AJIMEE は全タイミングで正解数が同じで、外れた問は 0。

打ち間違い 40 問(手を止めて Space)だけ 1 回目が 24 → 9 だったため、v4 の前のソース(Mozc 作業ツリー 8eae83f41)と
今のソースで評価用の実行ファイルを作り、交互に 3 回ずつ測った(`target/accuracy-guide/ab-v4/`)。

| | 手を止めて Space | すぐ Space |
| --- | --- | --- |
| v4 の前 | 23 / 23 / 23 | 16 / 16 / 16 |
| v4 | 23 / 24 / 23 | 16 / 16 / 16 |

差はなく、1 回目の 9 は測り方の揺れ(同じ実行ファイルの 2 回目は 21)。遅かった問(t26・t29・t31・t37)も同じで、
Space→候補の差は取り直しの間隔 1 回分(約 17 ms)。

## ライブ変換をオンにしたとき

`session_eval.py --live --config kotori_live_conversion=true`(打った後、取り直しが止まるまで待って未確定の表示を記録し、
その後 Space の 1 番目と比べる)。原票 `target/accuracy-guide/v4-live2/`。

| セット | オフの正解数 | 表示が正解 | 表示 = Space の 1 番目 | 最後の打鍵から表示まで(中央値) |
| --- | ---: | ---: | ---: | ---: |
| 日常(81) | 79 | 79 | 81/81 | 377 ms |
| 短文(120) | 118 | 118 | 120/120 | 323 ms |
| 同音語(40) | 39 | 39 | 40/40 | 370 ms |
| 打ち間違い(40) | 23〜24 | 26 | 40/40 | 541 ms |

最初の実装では打ち間違いの 4 問で表示が読みのまま残った。AI がその読みを採点せず、Mozc の綴りの補正
(「こんいちは → こんにちは」)が Space の 1 番目になる場合と、補正が数百 ms 遅れてできる場合。表示を
「Space を押したときの 1 番目」に合わせ、オンのときは取り直しを 0.1 秒おきに最大 30 回続けて直した(ADR0077)。

## 同音語のヒント

実際のセッション(`session_handler_main`)で Space を 2 回押して候補の窓を開き、候補の説明を見た。オンでは
「足: 靴・靴下 / 脚: 椅子・机」「回転: 車輪・寿司 / 開店: 新規・午前」「家庭のこと: 家族・夫婦 / 過程のこと: 製造・工程 /
課程のこと: 修了・博士 / 仮定のこと: 前提・仮説」。オフでは出ない。候補の並びは同じ。表にない語(暑い・熱い・厚い)には出ない。

## 内蔵 GPU

この PC(Ryzen 7 5700X + RTX 3060)には内蔵 GPU がなく、CI の Windows にも GPU がないため、**実機では未検証**。
専用 GPU のある PC と設定オフの PC では選び方が変わらないことを、上の回帰(専用 GPU で同じ結果)で確かめた。
既定はオフで、設定画面とリリースノートに「試験的」「未検証」と書いた。

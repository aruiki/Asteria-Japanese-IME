# 0068: 短文の語彙・頻度を補う公開辞書の検証

- 日付: 2026-10-22
- 状態: 実装・比較中、製品採用前
- 関連: REQ-6-2、REQ-14-2、カード81、0064〜0067

## 問題と対象

利用者は、製品の価値を「変換精度の高い日本語IME」とし、短文に必要な大規模データによる辞書対策を求めた。v2.0.0にはMozc OSS辞書と34,661連語があるが、Wikipedia取得は限定7MiB。前文あり・AI準備後94%を、単語・短文・前文なしの精度へ読み替えない。

正解候補の不在と、候補はあるが選択されない誤りを分ける。まず、更新が続くSudachiDict v20261015のsmall/core/notcore全CSVを語彙候補として固定する。Googleの内部データは利用しない。Sudachiの形態素解析用コストをMozcの接続/単語コストとしてそのまま使わない。語彙補強の検査と、コーパス頻度/連語/AI順位の改善を別々に測る。

## データの扱い

公式HTTPS配布からZIP、CSV、LEGAL、Apache-2.0全文、生成条件をSHA固定して取得する。UniDic・NEologd等の帰属を含むLEGALを残す。元コーパス/辞書本文はGitへ追加しない。取得・更新は固定情報の更新と再生成による明示的な操作とし、実行時通信を増やさない。

最初の候補は名詞だけを対象にする。読みのない語、制御文字、空白、不正な品詞、単語として使えない断片を拒否し、Mozcの品詞定義へ対応できるものに限る。既存の読み/表記の組は上書きしない。読み/表記/品詞が同じ候補を決定的に統合し、出典と除外理由を集計する。新語に限らず、従来辞書から欠ける一般語と固有名詞を調べる。

単語コストの初期案は、両辞書に共通する同一読み/表記の語から品詞ごとの分布を比較し、順位分位をMozcのコストへ対応する。Sudachiの数値を直接移さず、評価参照をコスト学習へ使わない。対応数が少ない品詞は採用を保留する。コスト方針・フィルターは最初の変換結果を見る前に固定する。候補化/第一候補/改悪を別に検査する。

## 比較前に固定する判定

公開v2.0.0のソース、converter、モデル、辞書、評価器、プロファイルを固定する。開発用の短文評価と未使用の短文評価を分ける。既存AJIMEE/日常/慣用句/ニュアンスは回帰とし、既存heldoutを調整に使わない。今回の新しい未使用評価も採否の最後に一度だけ開く。

- 新しい語彙候補は、開発短文の正解候補包含を悪化させず、候補欠落を減らすこと。第一候補の正味改善を測り、重大な意味/表記の改悪を残したまま採用しない。
- AIなし・Standard前文なし・Standard前文ありを分けて比較する。既存4開発セットの正解数を維持し、Standard AJIMEE90%以上の既存条件も守る。数値や参照を結果に合わせて変更しない。
- 表記の揺れや文脈のない同音語は、事前に定めた許容表記で評価する。単語登録があれば本人の意図まで一意に分かると扱わない。
- 解析/生成/展開/辞書ビルドの時間、追加辞書容量、変換時間とメモリを保存する。ダウンロード・生成の時間と入力時の応答を混同しない。
- 固定語彙全体からの選択規則で作り、評価IDや個別の正解語句による例外を作らない。開発評価で採用できなかった案の失敗も保持する。

本ADRの名詞候補だけでゴール全体を完了しない。大きなコーパスからの頻度/連語の更新、短文のGoogle日本語入力との同条件比較、導入済みMSI/active TIPの実入力、生成データの同梱・CI・配布候補、紹介文と画像への反映を続ける。AI主体の非同期表示、保護欄、ユーザー辞書、二重入力修正を維持する。

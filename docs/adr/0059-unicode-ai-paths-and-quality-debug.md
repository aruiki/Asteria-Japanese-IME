# 0059: 日本語パスでAIが無効になる問題を修正し、失敗例の抽出を再現可能にする

- 日付: 2026-10-12
- 状態: 利用者は実変換の内部開発と例の抽出を含む高速デバッグを指示

## 調査と決定

日本語フォルダーのDLLをKOTORI_RUNTIME_DIRに指定すると、WindowsのgetenvがANSIコードページで返す値をUTF-8として読んでいた。AIが動かずMozcへ戻ることを実変換で確認。通常の英数字インストール先では再現しない。同じDLL SHAの対照では日常65/81→79/81、AJIMEE102/200→183/200で、モデル品質そのものの変化ではない。

環境変数はWindowsのUnicode APIから取得し、Mozcの既存のWideToUtf8を使う。Linux側は従来のgetenvを維持。返す文字列はスレッドごと・キーごとに保持し、別の環境変数を読んでもポインターを壊さない。文脈TSVとAI状態の入出力もMozcのInputFileStream/OutputFileStreamにして、日本語の保存先を扱う。

Windowsで日本語・絵文字の環境値、値の変更、未定義の回帰テストを追加。実際に日本語DLLパスと日本語/絵文字の文脈ファイルで386問を確認。英数字の対照と全出力一致、Standard AJIMEE91.5%を維持。

## 精度改善の進め方

quality_triage.pyで前後とMozcの結果を問題IDで照合。データSHA/文脈条件/期待表記の違い、問題欠落/重複を拒否し、保存したok値を信用せず再判定する。公開ベンチマークの部分データを新たにコミットせず、25件の不一致例・前後文・Mozcの結果をローカルで再生成できるようにする。

386問の調整評価に含まれる既存セットから25件を抽出。うち3件はMozc正解からAIで不一致。「続編を書く→描く」「うかがえる→伺える」「消してね→消して寝」が次の対象。表記の許容幅に由来する不一致も含むため、25件全部を真の意味誤りとは断定しない。heldoutは調整に使わず、CLI値と実アプリの精度を区別する。

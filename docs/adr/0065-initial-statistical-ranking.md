# 0065: 初期候補を軽い文字統計で並べる実験

- 日付: 2026-10-18
- 状態: 実験。製品の変換経路へ未採用
- 関連: カード81、REQ-6-2、REQ-14-2、0064

AIなしの固定開発326件の不一致125件中103件は、観測候補に参照表記が含まれる。辞書の増量だけでなく、準備前の順位を改善する必要がある。「アイデア曲」も候補内にあり、上位の「局」と小さいコスト差で選ばれない。

まず評価CLIだけで既存の全文ラティス16候補とコストを取り出し、オフラインの文字1〜3gramを使う順位を調べる。通常IMEの本文ログは増やさず、大型モデルの同期起動・通信・入力中のファイルI/Oを追加しない。効果がなければ製品へ接続しない。

データは0064と同じ固定Wikipedia学習区間01〜07。今回の統計モデルは01〜06を学習、07からseed20261018で256文を較正へ分離する。読みと近似・同じ文を分離し、既存評価の読み/近似を双方から除外する。評価の正解表記を学習/較正へ使わない。Common Crawl/dev00、独立最終評価の正解を使わない。

文字統計はNFKC後、文頭2記号・文末記号を付ける。unigramの加算平滑化0.1、2/3gramの下位分布への事前重み8に固定。全文候補の元コスト差に、平均文字負対数尤度×読み文字数を加える。重量は0/25/50/100/200/400、採用差分は0/100/250、元コスト差の上限は既存連語と同じ3453に固定する。現在の表示候補も比較へ含める。

重量と差分は較正256文で選ぶ。既存正解の改悪を最小にし、その条件で改善数、次に小さい重量を優先する。0重量の対照を必ず含める。較正で改善しなければ不採用。選択後に固定4開発セットと通常28項目で改悪・包含/順位・応答性を確認する。評価の結果を見て重量・語句・正解集合を調整しない。

学習/較正/実験結果の原票・モデルはGitへ入れない。実行スクリプト、分割・生成条件・SHA、採否と失敗を保存する。採用する場合もユーザー辞書/確定履歴/変更禁止/保護フィールド/既存AI選択を優先し、キー経路の時間・メモリ上限を実測する。大きいモデルの起動待ちで基礎品質を代替しない。

## 較正で発見した表記保護の不足

v1は0重量を選択して不採用。非ゼロ重量には改善があったが、「第二弾」→「第2弾」の表記変更1件が全低重量候補に残った。参照を広げず、v1原票を保持する。数字表記・英字の大小・句読点/記号は弱い文字統計で変えない一般規則をv2へ追加し、同じ較正文だけで再選択する。文字統計は同じモデル、係数候補と改悪優先の選択基準は変更しない。まだ製品評価の結果を係数選択へ使っていない。

v2の較正は重量25/差分100を選択、256文で4改善/改悪0、変更17件。この係数と規則を固定し、固定4開発セットへ一度適用する。較正の基準は67/256、全文ラティス候補の参照包含118/256。新しい独立精度の合格判定には使わない。

# 0076. 打ち間違いの補正を「打ち間違いの確率 × 文の自然さ」で決める

- 状態: 採用(考え方・境目 2/3・打ち間違いの率は評価の前に決めた。5 に挙げた比べ方の直しと結果は評価のあと)
- 日付: 2026-10-27
- 関係: docs/adr/0036(打ち間違いの補正)、0074(打ったキーの単位と複数か所)。この ADR は両者の
  「直すかどうかの決め方」を置き換え、候補の作り方(書き換えの種類、絞り込み、探す時間)は引き継ぐ。
- 検証: [docs/verification/typo-posterior-20261028.md](../verification/typo-posterior-20261028.md)

## 背景

利用者から「補正の仕組みが論理的でない」と指摘された。v3.2.0 までの補正は、読みを書き換えた候補を
作り、AI の点(zenz と LLM の重み付きの和)が元の文より 5 以上高ければ書き換えていた(ADR0036)。

- 打ち間違いの起こりやすさを見ていない。隣のキーの打ち違いも、遠いキーの打ち違いも、2 か所の打ち間違いも、
  同じ「5」で扱う。前に「専門」がある 1 文字の「ご」(語)は、「の」の方が文として自然なので「の」に
  書き換えられた(ご→の は遠いキーの打ち違いで、起こりにくい)。
- 例に合わせた決まりが重なっていた。3 文字以下の読みは補正しない(`kMinCorrectionChars`、v3.2.0 の応急)、
  ず/づ・じ/ぢ だけを直す読みは差 1 で直す(`typo_strong_lp_`・`typo_soft_margin_`)、かなを削ると点が
  上がるのを 1 文字あたりの点で埋め合わせる、2 か所目は 1 以上上がるものだけを残す(`typo_llm_gain_`)。
- 採点に使う zenz の点は「その読みからその文になる確率」で、読みが違う仮説どうしを比べる量ではない。

## 決めたこと

読みの仮説ごとに、打ったキー x と意図した読み y について

    点(y) = log P(x | y) + log P(文_y | 前の文脈)

を取り、打った通り(y = x)の仮説も含めた事後確率 P(y | x) = exp(点(y)) / Σ exp(点) を出す。打ち間違いの
仮説のうち最も確率の高いものが **2/3 以上**なら書き換える。

### 1. P(x | y): 打ち間違いの起こりやすさ(`rewriter/kotori_typo_model.cc`)

意図したキーの列 y を打って x になる確率を、キーの打ち違い・抜け・余分・隣どうしの入れ替えの率から、
重み付きの編集距離(最も確からしい並べ方、最大 3 か所)で求める。打ち間違いのないキーは 1 - (率の和)。

| 種類 | 1 キーあたりの率 | 根拠 |
| --- | ---: | --- |
| 打ち違い | 1.65% | Dhakal ら 2018 の表 1(16.8 万人、全員の平均) |
| 抜け | 0.80% | 同上 |
| 余分 | 0.67% | 同上 |
| 隣どうしの入れ替え | 0.24% | Grudin 1983 の表 6.1(熟練者 6 人の平均で全誤りの 7.2%)を、上の 3 つの和に対する比に直した |

- 打ち違いの相手: 同じ段の隣 31%、上下の段の隣(同じ指)16%、残り 53% はほかの文字に等しく(Grudin 1983、
  熟練者)。隣は ADR0074 と同じ QWERTY の並び(上下の段は半キーずれる)。
- 余分なキー: 前後のキーとその隣、同じキーの重ねに 8 割、残りをほかの文字に(Grudin 1983 は、熟練者の余分な
  キーの大半が隣のキーを一緒に押したものと書く。8 割はその記述からの仮定)。
- かなの段の誤り(打つ前の、かなの思い違い)を別に置く。書き分けの迷い(ず/づ、じ/ぢ)と、い段のかなの後の
  拗音の小さい ゃ・ゅ・ょ の抜け(ちゅうしゅつ → ちゅうしつ)。キーで見ると、拗音の抜けは 2 か所の打ち間違い
  (syu → si)になり起こりにくく見えるが、実際は音の思い違いで 1 回の誤り。公開の打鍵データがないので、
  1 か所につき 0.5% と**仮定**する(隣のキーの打ち違いと同じくらい)。キーの打ち間違いと大きい方を使う。
  ADR0074 の「ず/づ だけ緩める」決まりは、この率に置き換わる。
- 隣どうしのかなの入れ替え(ござまいせん → ございません)は、1 回の入れ替え(上の 0.24%)と見る。ローマ字で
  打つ人はかなを 1 つずつ打つので、英語で文字を入れ替えるのと同じ単位の誤り。キーで見ると 2 か所以上になる。
- 率は、打っている間に直した誤りも含む値を使う。Dhakal らの「直されずに残った誤り」(1.17%)は、文を打ち終えて
  見直した後の値で、IME では Space を押す前に読みを見直さないことが多いため。
- 1 か所の打ち間違いは、打ち間違いのないときの e^-4.8(抜け)〜e^-7.8(遠いキーの打ち違い)倍。2 か所なら
  その積になる。
- 打ったキーは `ComposerData::GetRawString()`(ADR0074 と同じ。読みと合わないときやかな入力では、読みを
  ふつうの綴りに直したもの)。かなの単位で書き換えた読みは、変わった所だけを綴りに直したキーと比べる。
  し=si/shi、ん=nn/n のように綴りが複数あるかなは、打ったキー全体にいちばん近い綴り(P(打ったキー | 読み)は
  綴り方のうち最も確からしいもの)。抜けた ん は、後ろが で なら n 1 つの抜けで、nn の 2 つの抜けではない。

### 2. P(文 | 前の文脈): 文の自然さ

LLM(TinySwallow)の、前の文脈の後にその文が続く確率(読みは使わない)。文の終わりは付けないので、
続きがある読みの途中までの確率になり、打ちかけの読みの比べ方として合う。zenz は候補の文を作るのにだけ使う。

読みの仮説の点は、その読みに合う文のうち一番高いもの(読みの確率の近似)。文には、変換で選んだ文・その読みから
zenz で作った文のほか、かなのままの文も入れる。変換で選んだ文が打った読みに合わないとき(変換がすでに読みを
直していた。つずき → 「つづきをする」)は、合う読みの仮説の文として数える。ひらがなだけの文の読みはその文字の
ままとし、ず/づ を同じと見る辞書の照合は使わない。書き換えるときの表記は、読みを決めてから、その読みで
zenz が作った文にする(表記の選び方は変換の仕事で、LLM だけで選ぶと ひらがな の文を高く見ることがある)。

### 3. 直すかどうか

- 事後確率の境目 2/3 は、「正しく打った読みを書き換える損」を「打ち間違いを直し損ねる損」の 2 倍と見たときの
  損の期待値が小さくなる境目(2 / (2 + 1))。評価の前に決め、評価を見て動かさない(`KOTORI_LM_TYPO_POSTERIOR`
  は調べるための環境変数)。
- 読みの長さで補正を止める決まり(`kMinCorrectionChars`)は外す。1 文字の読みでも、打ち間違いの起こりやすさが
  書き換えを防ぐ(専門+ご: ご→の は遠いキーの打ち違いで e^-7.7。の が 語 より 2,000 倍以上自然でないと
  書き換えない)。
- 生成で直す補正(`FindLlmCorrection`、ADR0036 の後に足した LLM の補正)も、読みを変える直しは同じ事後確率で
  決める。読みを変えない直し(同じ読みの別の表記)は打ち間違いではないので、これまでどおり並べ替えと同じ点で比べる。

### 4. 探し方(ADR0074 から引き継ぎ、決め方だけ変える)

候補の読みの作り方、辞書のコストでの絞り込み、1 か所ずつ直して上位 3 つから次へ進むこと、探す時間、
Space を押してからの軽い補正、試すかどうかの関所(選んだ文の 1 文字あたりの点。速さのため)は変えない。
変えたのは、伸ばす読みと文を作る読みを並べる点で、かなのままの LLM の点に打ち間違いの起こりやすさを足した
もの(事後確率の近似)にした。探す幅(4、ADR0074 と同じ)の基準は、打った通りの読みではなく、いちばんよい
書き換えにした。かなのままの点は、漢字の文にしたときの差をずっと小さく見積もるので(誠に失礼しました: かなで
7.5、文で 19.7 上がった)、打った通りと比べると正しい直しも落とす(ちゅうしゅつ は、かなでは打った通りより
下がった)。書き換えどうしの並びは、かなのままでもおおむね保たれる。かなを削ると点が上がる問題は、削るには
余分なキーを打ったことになる確率が受け持つので、1 文字あたりの点の埋め合わせは外した。文の採点は zenz を
使わなくなったので、候補ごとの zenz の採点(1 回ずつ)はなくなった。

`KOTORI_LM_TYPO_MARGIN`、`KOTORI_LM_TYPO_LLM_GAIN`、`KOTORI_LM_TYPO_STRONG_LP`、`KOTORI_LM_TYPO_SOFT_MARGIN` は
なくなった。`KOTORI_LM_TYPO_WINDOW` は基準を変えて残した。

### 5. 作る途中で見つけて直した比べ方の誤り

境目 2/3 と打ち間違いの率は、評価の前に決めたまま変えていない。評価の途中で直したのは、ここに決めた考え方の
とおりに計算できていなかった所(記録は検証記録)。

1. 拗音の抜けを 2 か所のキーの打ち間違いと数えていた(抽出)。かなの段の誤りにした。
2. 変換で選んだ文を、打った読みの仮説の文として数えていた(続き)。読みの合う仮説の文にした。
3. 幅の基準が打った通りの読みだった(抽出)。いちばんよい書き換えにした。途中で幅をなくしたら、手を止めている
   0.7 秒に探しきれず、Space で打ち切られて 5 問直らなくなったので、基準を変えて戻した。
4. かなの入れ替えをキーの 2 か所以上の打ち間違いと数えていた(申し訳ございません)。1 回の入れ替えにした。
5. 抜けた ん を、いつも nn の 2 キーの抜けと数えていた(新幹線)。打ったキーに近い綴りにした。

速さのために変えたこと(決め方は変えない): 意図したキーは AI で採点する読み(80 個まで)についてだけ作る。
打った通りの確率はキーの数から直接出す。手が止まった間の深い補正では、候補の文を点の高い順に 5 個ずつ作り、
2 組目からは探し始めて 200 ms(`KOTORI_LM_TYPO_SEARCH_MS`)を過ぎていたら作らない(ふつうの文でも書き換えの
候補が残り、毎回 10 個作ると手を止めた間に終わらず、Space を待たせた)。

## 考えたが採らなかったこと

- 率を Aalto の 1 億 3,600 万打鍵のデータから数え直す: データの条件が研究・非営利での利用に限られ、配布物の
  作成に使うと条件が合わない。論文の表の数値(事実)だけを使い、データは取得も同梱もしない。
- Mozc の `data/typing/`: スマートフォンのキーボード向けの、ローマ字の並びの起こりやすさ(言語の側)で、打ち間違いの
  起こりやすさではない。PC の打ち間違いの表は Mozc にない。
- 事後確率の境目を評価セットで選ぶ: 評価に合わせた決まりを作り直すことになる。

## 受け入れる不足

- 率は英語の書き写しの研究のもので、日本語のローマ字入力で測ったものではない。かなの段の誤りの率は仮定。
- LLM(1.5B)の確率は、文の自然さの近似。
- 事後確率は、作った候補の読みの中だけで比べる(作らなかった読みは数えない)。

| 評価セット | v3.2.0 | この変更 |

| 打ち間違い(40)既定・すぐ・0.15 秒 | 24・16・15 | 24・16・15 |
| 利用者の打ち間違い 5 例(既定) | 3 / 5 | 3 / 5 |
| 利用者の報告(専門+ご など 6) | 6 / 6 | 6 / 6 |
| 日常・短文・同音語(全タイミング) | 79・118・39 | 79・118・39 |
| AJIMEE(前文あり) | 187 / 198 | 187 / 198 |

全セット・全タイミングで v3.2.0 から外れた問は 0(前日の v3.2.0 の原票と比べても 0)。ふつうの文の Space の
p95 は 1〜2 ms の差。正解数は増えていない: 決まりを考え方に置き換えても、直せる問は同じだった。
3 文字以下の読みも補正の対象に戻したが、専門+ご は打ち間違いの起こりやすさで「語」のまま(事後確率 0.015〜0.054)。

判定用のセット(文脈の選択・文章)は v3.2.0 と同じ。調整用の文脈の選択(choice-dev)は 221 → 219 で、外れた 2 問は
補正が書き換えたものではなく、前の問の計算で LLM の状態が変わり、ほぼ同点の 2 つの点が入れ替わったもの(2 問だけを
測ると v3.2.0 も同じ答えになる。検証記録)。

受け入れた不足:

- 手を止めている 0.7 秒にぎりぎり収まる問(しんかんせでかえります)は、今日は v3.2.0 でも直らないことが多く
  (3 回中 1 回)、この変更の後は 14 回中 3 回。補正の段が v3.2.0 より 3〜20 ms 長いことがある。
- 途中で直った ごかくいん → ご確認 は、ふつうの文の Space の待ちを戻すために候補の文の数を時間で絞ったら、また
  直らなくなった。

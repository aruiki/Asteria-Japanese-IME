# 0064: AI準備前の初期候補に公開コーパスの連語を使う

- 日付: 2026-10-18
- 状態: 開発枝へ採用。MSI同梱とローカル検査済み、実TSF/公開は未完了
- 関連: REQ-6-2、REQ-9-2、REQ-14-2、カード81

## 問題

前文なしの初期変換の基礎品質をユーザーが問題視した。既存開発100問で、本製品のAIなし経路57/100、準備後95/100。AI準備後だけの改善では初期候補の品質を解決しない。固定MozcのOSS連語データは40件で、既存のCollocationRewriterを拡張する余地がある。

## 実験する変更

既存MozcのBloom filterと候補のcost差/品詞/表記の制約を使う。大型モデル、実行時ファイル読取、通信を追加しない。単語や評価IDの分岐は持たない。

固定済みzenz-v2.5-datasetのWikipedia由来train区間01〜07から、3〜14文字の日本語の組合せを抽出する。5つ以上の異なる文・2つ以上の取得区間に現れることを要求する。Wikipediaのdev区間00とCommon Crawl区間は使わず、既存評価の読みと近似読みを除外する。抽出に参照表記を渡さない。

比較前に生成条件とデータを固定。元の40件を保持して8,405件を追加、合計8,445件、SHA f576ffc696ad81f244fb5791a2571ac1edb320f2a2f20d0773ea6a044f01b29c。データ本文はコミットしない。出典・固定SHA・生成コマンドは`training/collocations/README.md`。

連語補正は、上位にAI選択済み/ユーザー辞書/NO_MODIFICATION/コマンド属性がある要求を変更しない。入力世代、候補ID、読み、文節を変えず、既存の候補移動だけを使う。

## 採否の確認

固定済み4開発セットの同じ参照・前文なしで、AIなしの改善/改悪を比較する。既存正解の改悪を隠さない。既定Standardの前文あり4セットと前文なしAIも比較し、AI準備後の品質を下げない。保護回帰・AI不在のnative入力と応答性を確認する。

基礎品質の改善がなければデータ量の増加を成果とせず不採用とする。結果を見て語句の個別削除/追加や参照集合の変更で合格させない。初回「あいであきょく」、Google版との差、実TSF、配布確認は別に残る。

## 判定

同じ978出力の比較でAIなしAJIMEEが102→103/200（改善1/改悪0）、他の出力はすべて一致した。基礎候補への小さい改善として採用し、大幅改善とはしない。AIなしの通常変換/操作28項目、基礎部品C++165件、同じ256MiB制限でAI失敗時6入力を確認。固定公開区間からの取得/生成、CIの配置、MSI必須同梱、固定SHA/出典検査へ接続した。詳細は[検証記録](../verification/accuracy-fast-collocations-20261018.md)。初回「アイデア局」の失敗は新MSI資産でも残り、通常変換全体の完成とは判定しない。

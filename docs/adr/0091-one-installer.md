# 0091. 1 つの exe のインストーラーにし、NVIDIA の高速化は自動で入れる

- 状態: 採用
- 日付: 2026-11-25
- 関係: docs/adr/0086(MSI の上限)、0088(CUDA の追加パッケージ)

## 背景

利用者(2026-11-25): 本体と CUDA の追加パッケージが別だと分かりにくい。1 つにして、PC で自動で見分けてほしい。

本体の MSI(v5.4.0 で 1,575,718,912 バイト)と CUDA の追加パッケージ(536,281,088 バイト)を 1 つの MSI にすると
約 1.97 GiB で、MSI の上限(1.8 GiB、0086)を超える。

## 決めたこと

1. **WiX の Burn で 1 つの exe(`Asteria-Setup.exe`)にする**(`mozc/bundle/`)。中に本体と追加パッケージの MSI をそのまま持つ。
   MSI はそれぞれ上限の内側のままなので、0086 の制約に触れない。
2. **NVIDIA の高速化は、CUDA 13 が動くドライバー(580 以降)があるときだけ入れる。** System32 の `nvcuda.dll` のファイルの
   版で見分ける(ドライバー 580.97 は `32.0.15.8097`、621.40 は `32.0.16.2140`。条件は `32.0.15.8000` 以上)。
   見分けを誤っても、変換サーバーは版の札が合わない・読めない高速化を使わず Vulkan で動く(0088)ので、変換は止まらない。
3. **画面は WPF で作る**(`mozc/bundle/ui/`、.NET Framework 4.7.2、Burn の managed bootstrapper application)。WiX の標準のテーマでは
   色・角丸・余白を作り込めないため。利用者と詰めた形: 明るく平らな画面にアイコン・名前・版、ボタン 1 つ、細い進捗バー、
   % と残り時間、扱っているファイル、ヒント。NVIDIA の高速化は表示せずに入れる。`/quiet`・`/passive` では窓を出さない。
   `AsteriaSetupUI.exe --preview <フォルダー>` で各画面を PNG に描ける(何も入れない)。
4. 実行時の通信は増やさない(すべて exe の中にある)。
5. ~~今までの `Asteria64.msi`・`AsteriaCuda64.msi` も添付を続ける(README・サイトの固定リンク、管理者の一括導入のため)。~~
   **2026-11-26 に変更**: 利用者の指示で、リリースに添付するのは `Asteria-Setup.exe` と `checksums.txt` だけにする。
   MSI と `.sha256` が並ぶと、初めての人がどれを落とせばよいか迷い、`.sha256` をインストーラと取り違えるため。
   SHA-256 は「インストールには不要」と書いた `checksums.txt` 1 つにまとめる。v5.5.0 から適用。

## 残すこと

- **GitHub の 1 ファイル 2 GiB に近い。** v5.4.0 で 2,109,738,058 バイト、残り 36 MB。超えたら `build_bundle.ps1` が止める。
  モデルを大きくするときは、exe から高速化を外して、0086 のように受け取る形(管理者権限でインストール先に置く)を検討する。
- NVIDIA の GPU がない人も 0.54 GB 多くダウンロードする。

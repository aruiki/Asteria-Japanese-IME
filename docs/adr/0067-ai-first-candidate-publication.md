# 0067: GPU AIの初回結果を待って候補を公開する

日付: 2026-10-19。状態: 利用者の明示指示に基づく実装中。

## 判断

利用者は「AIが候補を出すまでは変換候補を出す必要がない」「このソフトはそもそもAIがメインでGPUで動かす前提」と明示した。通常の候補表示を即時Mozc応答にする従来の判断を改める。ADR0039の非同期callbackと評価結果の再利用を活用する。

Mozcは辞書・形態素・分節・候補素材・履歴・OS統合を担当する。入力中は読みを表示・編集できる。正常なAI準備・推論中は候補一覧を公開せず、Space要求を非同期に保留し、AIの初回結果が完成してから変換を表示する。モデルの読込と推論を打鍵スレッドへ移さない。

## 配送

- `Segments::KotoriAiStatus`で待機・評価済み・利用不能を区別する。読込・競合は失敗扱いしない。ワーカーの失敗は入力世代・読み・文脈・設定に限定する。
- 入力中の候補一覧と全候補出力は未評価の間抑える。準備が長くてもcallbackの従来回数上限でMozc候補へ切り替えない。
- Spaceの準備で得た文節そのものを変換へ渡す。表示直前の再採点による順位変更を避ける。
- Space後のEnterは結果到着後に確定する。Enter後の次の打鍵は順序を保存し、読みを仮表示しながら前の確定後に通常の入力処理へ渡す。
- Enter前の編集・取消、欄変更・リセットは待機要求と古い結果を失効させる。別欄へ古い結果を配送しない。
- AIを明示的に切った場合、保護欄、実際のモデル失敗・処理期限切れなどは入力継続の例外経路とする。フォーカス側の即時確定要求では表示中の読みを返し、後続打鍵を消さない。

## 検証

モデルなしの状態遷移試験と、固定EXE・同じモデル/DLLを使った隔離SessionHandlerの前後比較を行う。隔離試験はTSFの実アプリ受入れと区別する。Standard AJIMEE90%以上と既存の辞書・学習・候補操作を維持する。新しいMSIとWindows CIの確認前に公開済みRCの挙動が変わったとは記載しない。

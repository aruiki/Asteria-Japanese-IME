# 0092. インストーラーは数 MB にし、MSI はインストールのときに受け取る

- 状態: 採用
- 日付: 2026-11-26
- 関係: docs/adr/0091(1 つの exe)、0086(MSI の上限・追加の AI の受け取り)、0088(CUDA の追加パッケージ)

## 背景

利用者(2026-11-26): 1.96 GB の `Asteria-Setup.exe` は今後の開発の支障になる。Setup は MB で落とせるようにして、
Setup が中身を落とす形にしてほしい。置き場所は要検討。

0091 では 2 つの MSI を exe の中に持たせたため、exe が GitHub の 1 ファイルの上限(2 GiB)まで残り 36 MB だった。
モデルを大きくするたびにこの上限に当たる。NVIDIA の GPU がない人も、使わない 0.54 GB を落としていた。

## 決めたこと

1. **exe には画面(WPF)だけを入れ、2 つの MSI は Burn のリモートペイロードにする**(`Compressed="no"`・`DownloadUrl`)。
   exe は約 1.1 MB(v5.5.0)。Burn は作ったときの MSI の大きさとハッシュを exe に書き込み、受け取ったものが一致しなければ使わない。
2. **置き場所は別のリポジトリ `aruiki/asteria-downloads` の Releases**(利用者が選んだ案)。版と同じ名前のリリース
   (`v5.5.0` など)に `Asteria64.msi` と `AsteriaCuda64.msi` を置く。URL は
   `https://github.com/aruiki/asteria-downloads/releases/download/v<版>/<名前>`。
   - 比べた案: Hugging Face(1 ファイルの上限がほぼないが、アカウントが要り MSI は用途外)、Cloudflare R2 と自分のドメイン
     (URL を持てるが契約が要る)、同じリポジトリの別タグ(手軽だが Releases の一覧に並び、初めての人が迷う)。
   - 別のリポジトリにすると、本体のリリースは `Asteria-Setup.exe` と `checksums.txt` だけのまま(0091 の 2026-11-26 の変更)。
     無料で転送量の上限がなく、追加の AI(0086)と同じ GitHub から受け取る。
3. **高速化を入れない PC は、高速化の MSI を受け取らない**(Burn は入れないパッケージを取りに行かない)。
4. **exe と同じフォルダーに同じ名前の MSI があれば、受け取らずにそれを使う**(Burn の標準の動き)。ネットにつながらない PC には、
   exe と 2 つの MSI を同じフォルダーに置いて渡せばよい。
5. 受け取っている間は、画面に「ダウンロードしています」と大きさ(「0.84 GB / 1.57 GB」)を出す。受け取れなかったときは、
   インターネットへの接続を確かめるよう案内する。
6. MSI の中身を変えたら exe も作り直す(exe に MSI のハッシュが入っている)。`build_bundle.ps1` が最後に上げる手順を表示する。

## 仕様との関係

REQ-12-4 の例外に、インストーラーがインストールのときだけ MSI を https で受け取ることを足す(メンテナの指示による)。
変換サーバーは今までどおり通信しない。インストーラーが送るのは HTTP の GET だけ。

## 残すこと

- 1 つの MSI は 1.8 GiB まで(0086)、GitHub の 1 ファイルは 2 GiB まで。本体の MSI が上限に近づいたら、モデルを別の
  MSI(または 0086 のような受け取り)に分ける。分けた MSI も同じリリースに置けば、exe は数 MB のまま。
- 配布用のリリースを消すと、その版の exe は入れられなくなる。古い版のリリースも消さない。

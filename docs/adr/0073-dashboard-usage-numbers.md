# 0073. ダッシュボードに使い方の数字を出し、応援の通知を3日ごとにする

- 状態: 採用
- 日付: 2026-10-24
- 関係: docs/adr/0072(インストーラー)、GOAL.md「Asteria v3.0.0 正式版の要件」

## 背景

設定画面のダッシュボードは、PC 全体の CPU・メモリとグラフ、意味の分かりにくい「AI 計算の累計」を出していて、
利用者に「何が伝えたいのかわからない」と指摘された。利用者は「思考時間 ms、変換回数、正答率、節約できた時間のような
有益な情報」を求めた。応援の通知(GitHub の Star のお願い)は週1回で「頻度が低く意味がない」、一方で
「普段使うときにあると邪魔」なので設定で止めたい、と指示された。

## 決めたこと

- ダッシュボードは「使えるか」「今日の使い方」「このPCで使っているもの」「応援」の4つにする。
- 今日の使い方は4つの数字。今日を大きく、累計を小さく出し、日付が変わると今日の分を 0 に戻す。
  - 変換した回数: Space で変換して確定した回数。
  - 考える時間: Space から候補を出すまでの平均(ms)。モデルの読み込みを待った回(10 秒超)は数えない。
  - 正答率: どの文節も1番目の候補のまま、区切りも変えずに確定した割合。
  - 予測で節約できた時間: 予測の候補で確定したとき、まだ打っていなかった読みの文字数 × その人の1文字あたりの
    平均入力時間(打ち始めから変換・確定までの時間から学ぶ)。速さをまだ知らないうちは時間を 0 とし、推測で水増ししない。
- 保存するのは回数と時間だけ(プロファイルの `asteria_usage.txt`、key=value の数字の行)。入力した文章や読みは
  保存しない。パスワード欄とシークレットモードでは数えない。実装は `session/kotori_usage_stats`。
- 応援の通知は、使い始めて3日後に初回、その後は3日ごと。「GitHub で応援する」を押した後も30日後にもう一度出す。
  以前の版で押して止めた人には「以後表示しない」と約束したので出さない。設定画面の「その他」の末尾に、
  表示するかのチェックを置く(目立たせない)。Star したかの確認は GitHub への通信が要るので次の版で検討する。

## 結果

試験: `session:kotori_usage_stats_test`、`session:session_test`(Space の変換と確定で数が増える)、
`gui/config_dialog:kotori_dashboard_test`、`gui/tool:kotori_support_reminder_test`。画面は撮影して確かめた
(`docs/verification/release-v3.0.0-20261024.md`)。

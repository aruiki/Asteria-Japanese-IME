# 0080. 英語の名前をローマ字のまま打てる(既定オフ)

- 状態: 採用
- 日付: 2026-10-28
- 関係: docs/adr/0076(打ち間違いの補正の事後確率)、0077(ライブ変換)、0079(同音語のヒント)

## 背景

利用者(2026-10-28): 日本語と英語を切り替えずにローマ字で打ちたい。以前、半角英語を未確定のまま浮かせる方式を作ったが、
ショートカットなどとぶつかって失敗した。浮かせるのはいつもの日本語の未確定文字にして、英語のつもりだった所だけを変換で
英語にすれば問題ない。英会話ではなく、「ぎてゅｂ」「あっｐぇ」「かぃぃぬx」「うぶんつ」のような英語の名前に使えればよい。
文脈があるので、ちゃんと第一候補に出ること。日本語と競合する語の扱いに気をつけること。

## 決めたこと

- 設定 `kotori_romaji_english`(既定 false)。設定画面の「AI 変換」に「英語の名前をローマ字のまま打てる」。
- 打ったキー(`Composer::GetRawString`)のうち、英語の一覧にある綴りを、左から重ならないように、その位置でいちばん長い語で
  探す(`kotori::RomajiEnglishWord`)。一覧は、製品名・サービス名・技術用語の一覧(GitHub、Linux、Ubuntu など。3 文字以上)と、
  同梱のカタカナ英語辞書の英字だけの語(5 文字以上。大文字を含む表記を優先)。日本語の語として読める名前(toyota など)は入れない。
- 英語にする所より前の部分は、打った読みの先頭とそのまま合うこと(日本語の語の途中から英語にしない)。
- 一般の語は、その所のかなが日本語の語として辞書にあれば試さない(sake → さけ、kite → きて)。一覧の名前は、辞書にカタカナの
  読みがあっても試す(うぶんつ → ウブンツ)。
- 1 語ずつと、すべての語(2 語以上のとき)を英語にした文を作る。日本語の部分は zenz で作る。前の文脈の後に続く文として
  LLM が今の 1 番目より `english_margin_`(2.0)以上自然と見たときだけ、その文を 1 番目にする(文脈で第一候補を決める)。
  英字の大文字と小文字だけが違う(chrome → Chrome)ときは、点の差を問わず正しい表記にする。
- 英字は打った通りの半角のまま出す(`NO_VARIANTS_EXPANSION`)。
- Mozc の打ち間違いの補正が 1 位のときも試す(ユーザー辞書の語は変えない)。辞書を引くだけで、当たりがなければ LLM を
  呼ばないので、Space を押して待っているときも試す。LLM のない PC(Low)では使わない。

## 結果(2026-10-28、RTX 3060、Standard、`session_eval.py --context`)

| セット | オフ | オン |
| --- | ---: | ---: |
| 英語の名前(20、`asteria-romaji-english-20261028`) | 0 | 19 |
| 競合する語を含む日本語(24、`asteria-romaji-english-conflicts-20261028`) | 19 | 19(すべての問でオフと同じ文) |
| 日常・短文・同音語・打ち間違い・利用者の報告・AJIMEE | 79・118・39・23・6・187 | 同じ(英語になった文 0) |

オンで正しくなった例: github → GitHub、githubnipusshusuru → GitHubにプッシュする、linuxnoinsuto-ru → Linuxのインストール、
ubuntuwoirete → Ubuntuを入れて、githubtolinux → GitHubとLinux、chromegaomoi → Chromeが重い。

変わる(ローマ字そのものの曖昧さ)。原票 `target/accuracy-guide/ab-en/`。

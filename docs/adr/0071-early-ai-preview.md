# 0071. 手が止まって 20 ms で Space と同じ変換を裏で始める(GPU)

- 状態: 採用
- 日付: 2026-10-24
- 関係: docs/adr/0039(入力中の候補の取り直し)、0067(AI の結果を待って候補を出す)、0070(続きの生成の廃止)

## 背景

入力中の候補の取り直し(と、それに伴う Space と同じ AI の変換)は、GPU のある PC で最後の打鍵から 200 ms 後に
始めていた。人は最後の打鍵から 0.1〜0.2 秒ほどで Space を押すので、多くの場合は Space の時点で計算が始まっておらず、
生成と採点(合わせて約 0.1〜0.2 秒)の分だけ待っていた。

## 決めたこと

- GPU のある PC では、最後の打鍵から 20 ms で取り直しを頼む(`KOTORI_LM_LIVE_FIRST` で変えられる)。続けて打てば
  次の打鍵で計算をやめるので、入力は待たない。GPU の計算は増える(利用者の方針: 速さと精度のために計算を惜しまない)。
- GPU のない PC は 450 ms のまま(CPU では途中でやめる計算が重い)。

## 結果

最後の打鍵から 150 ms で Space を押す(`session_eval.py --space-gap 150`)開発用 short/doc で、Space から候補表示まで:
200 ms のとき中央値/p95 142/260 ms・207/360 ms、60 ms のとき 52/159・114/270、20 ms のとき 20/118・77/228。
正解数は同じ。詳細は `docs/verification/release-v2.1.0-20261023.md` の「速度の改善」。

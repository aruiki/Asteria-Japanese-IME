# ADR0049: 利用者改善の統合とローカルでの配布準備

状態: 実装・検証中。2026-10-09。カード64、ADR0040〜0048。

利用者の「すべての要望を改善して最後にリリース」「build等はすべてローカル」を今回の作業順序とする。
以前の枝は保持し、生成補正・予測/Tab整合・意味候補・ダッシュボードを1つのソースへ統合する。

## 初回表示と予測

2026-10-19追補: ユーザーの通常変換の必要条件と実シナリオの失敗に基づき、以下の「候補欄だけを非同期の評価結果まで待つ」は取りやめる。Mozcの通常候補を直ちに残し、準備後のAI候補を同じ世代・保護条件で更新する。通常予測がAI待機/故障で消えないことをred/greenで確認した。[検証記録](../verification/accuracy-normal-conversion-20261019.md)。

読みは即時に表示する。候補欄だけを非同期の評価結果まで待ち、時間上限後は通常変換に戻す。
通常設定で生成補正を有効にする案を検証する。利用者はAIタブのチェックボックスで補正を無効にできる。
名前・数値・単位・文法語・代名詞と入力世代/読み/文脈/モデルの既存の保護を維持する。

続きの確信度には入力済みの全文の平均点を混ぜず、同じ本文の後に続く文字列の条件付き平均点と次点差を使う。
現在の試作は平均点-1.4以上・差0.5以上。正答確率を表す値ではない。完全な読みが求まり、評価済み本文を保持する
候補だけを初回とTabの両方で採用する。弱い続きは選択肢に残す。開発セットで確認し、heldoutの調整はしない。

自由生成の補正は40文字以下の入力の局所修正を対象とする。日本語LLMが生成した読みから一字の
促音/長音の脱落、重複、濁点違いを調べ、元の正しい漢字・周囲の表記を保持して反映する。
逆引きの最初の読みだけに依存せず、入力に近い一字修正と辞書の対応を照合する。
この経路は変更範囲のかなだけを修正し、保護語と否定/時制/活用の断片を保持する。
一文字の助詞が単語内に重なった場合の過剰拒否だけを避け、通常の同音語補正の文法保護は維持する。
数値・単位の検査と採点差5.0は緩めない。名前の正規化や一般的な文章の言い換えは自動で行わない。
補正は入力世代・所有者・モデル・設定を照合する。Tabを取り消した後の失効結果を再採用しない。

## 意味の選択肢とUI

特徴/特長などの説明つき候補を優先する。同音で漢字が複数あるだけでは意味の近さを証明できない。
利用者の医者/慰謝の失敗で、一般の同音語を無条件に優先する案を撤回した。説明できる語組だけを優先し、
それ以外のMozc候補は元の文節内に残す。AIの根拠のない選択肢を追加して変換品質を下げない。
数量変更・語尾/助詞変更・一字のかな化を優先候補へ昇格させない。変更箇所の最小の連続文節へフォーカスし、
Mozcに同じ読みと範囲の実候補があればそのまとまりを保つ。文のほかの部分を確定したり学習したりしない。
AIによる文節伸縮後のFIXED_BOUNDARYでも、読み・境界を変えない意味の選択肢は提示する。
FIXED_VALUEと保護属性は引き続き拒否する。7文節の実例と変更箇所への選択を回帰試験へ追加した。
文字種は表示だけを除き、内部候補IDとF6〜F10の直接変換を保持する。
候補の配色はWindowsのダーク/ハイコントラストに対応する。設定画面はWindowsの標準の操作部品とフォントを使う。
名称をKotoriとし、実状態・計算時間・CPU/メモリと推移をダッシュボードで表示する。
AI計算時間は入力応答時間と区別し、取得できない値は未確認と表示する。支援ページはボタンを押した時だけ開く。

## ローカル配布の扱い

通常workflowの停止・テストの無効化・CI環境の偽装は行わない。ソースのBUILDを6330の数値として固定し、
MSIのProductVersionの先頭3項目がrc.3の3.34.6322より大きいことを確認する。
将来のworkflowは数値のBUILDも受け取り、その公開番号を超えて更新する。
今回のbuild/test/モデル評価/MSI内容検査は開発機で実行し、モデル評価とbuildを同時に実行しない。
パッチを源ツリーから再生成し、新規cloneへの適用結果をビルド入力と照合する。

公開対象はソースコミット・入力manifest・MSI/EXE/model/dataのSHA-256で固定する。
インストール済みTIPによる実アプリの入力・上書き更新・削除を、CLIやQt描画やMSI展開だけでPASSとしない。
実機確認ができない場合は完成/公開完了と扱わず、作成済みMSIと検証原票を保存して残る条件を具体的に伝える。
v1.1の配布は引き続きrcのプレリリースで、既存の正式版Latestは維持する。

## 測定

最終ソースと成果物の測定結果はdocs/verificationのall-user-improvements記録へ追記する。
過去の失敗ログと別の枝の検証記録はその時点の結果として保存し、PASSへの書換えはしない。

## rc.4の実入力不合格を受けた修正

BUILD6330の実ファイルの同一性を確認した上で、利用者観測を実入力FAILとして保存する。
取り直しはSpaceと同じ入力開始時のclient_contextで評価する。TSFタイマーには周囲の文が
再送されないため、その空のContextを新しい採点に使わない。文脈の前後が欠落することを
単体テストで修正前FAILとして再現し、修正後も同じアサーションを維持する。
Windowsの更新先はGetTopで判定し、非同期編集セッション実行時も再照合する。
根拠はMicrosoftのEdit Contexts（https://learn.microsoft.com/en-us/windows/win32/tsf/edit-contexts）。
新しいソース/MSI/実入力は古いPASSと混同しない。モデルロード中の即Spaceでは通常変換に
戻る境界が残るため、準備済みのCLI結果だけで初回問題全体の解決を宣言しない。

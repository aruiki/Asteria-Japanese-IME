# 0069. AIをログイン時に読み込んで常駐させ、入力がなくても外さない

- 状態: 採用
- 日付: 2026-10-23
- 関係: docs/adr/0034(しばらく入力がなければ外す。この既定を変える)、0067(AIの結果を待って候補を出す)、GOAL.md 2026-10-22

## 背景

利用者との合意(GOAL.md)は「AIはWindowsログイン時に常駐・読込して、変換時の待ちを無くす(VRAMを常時使用する)」。
ログイン時の読み込みはすでにある(MSIが `Kotori Prelauncher` を HKLM の Run に登録し、`mozc_broker --mode=prelaunch_processes`
が mozc_server を起動する。サーバーは起動すると裏でモデルを読み込む)。

一方、0034 で入れた「最後の要求から10分でモデルを外す」が既定で有効だった。0034 の時点では外した後の最初の変換は
AIなし(Mozcの結果)で出していたが、0067 でAIの結果を待って候補を出すようにしたため、10分以上手を止めた後の
最初の変換は、読み込み直しを待つようになった。

## 決めたこと

- `idle_unload_ms_` の既定を 0(外さない)にする。ログイン時に読み込んだモデルを常駐させる。
- `KOTORI_LM_IDLE_UNLOAD`(秒)を指定したときだけ、0034 の動作(外して、次の入力で読み込み直す)をする。
  VRAMを空けたい利用者向けの設定画面の項目は、要望があれば足す。
- AIが起動できない(モデルや llama.dll がない、読み込みの失敗)ときは、待たずにMozcの候補で変換を続ける(変更なし)。

## 結果

`mozc/tools/first_conversion.py`(実際のIMEと同じセッションの経路、RTX 3060)で、Spaceから候補が表示されるまでの時間を測った。
数値と原票は `docs/verification/release-v2.1.0-20261023.md` の「(3) ログイン時の常駐」。

## 採らなかった案

- 外すまでの時間を延ばす: 長く手を止めた後の最初の変換で待つことは変わらない。
- 外した後の最初の変換だけMozcの結果を出す(0034 の元の動作): 0067 の方針(AIの結果を待って候補を出す)と合わない。

# 0062: Mozcの入力補正をAIが取り消さない

- 日付: 2026-10-12
- 状態: 採用。カード77の万単位探索から抽出した回帰修正

## 問題

「こんいちは」でMozcは「こんにちは」を作れるが、AIが元の読みの字面に近い「今日は」を優先する。「りょうしゅしょをください」も「領収書をください」から「領主書を下さい」へ戻る。KeyCorrectorが辞書語へ補った由来が候補に届かず、AIが通常の候補として採点していた。

## 判断

特定の文章をホワイトリスト化せず、KeyCorrectedNodeListBuilderで辞書側のactual_keyと元入力に対応するnodeのkeyが違う場合だけNode::TYPING_CORRECTIONを付ける。NBestGeneratorで既存のCandidate属性へ引き継ぎ、文節と文全体の両方に由来を残す。

変換中の先頭候補にこの属性がある場合は、自動の文全体キャッシュ適用・生成・AI再採点で取り消さない。2位以下の補正候補だけ、履歴文節だけの場合は止めない。通常の入力やユーザーによる候補選択は維持する。既存のユーザー辞書候補の保護も維持する。

文全体のAI処理を保守的に止めるため、補正が含まれる文の別の部分をAIが改善する機会は減り得る。部分だけ固定して再採点する方式は境界・候補の整合性に追加設計が必要であり、今回の修正には混ぜない。

## 確認

修正前に実ラティスの補正属性欠落テストが失敗。修正後は文節・文全体の両方の属性を検査する。通常の「こんにちは」には補正印を付けない。

40例×高速/待機/0.15秒打鍵のAI ON比較で、上記2例が全3条件で改善、他114出力は不変。AI OFFの同じ条件も保存。調整用386問は全出力不変、AJIMEE183/200=91.5%維持。性能改善の主張はしない。

原票と検証範囲は docs/verification/large-input-campaign-20261012.md。隔離SessionHandlerの結果をWindows TSF実入力、導入版、MSI検証とは扱わない。

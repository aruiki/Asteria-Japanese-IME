# 0061: 万単位の実入力探索を精度開発の入口にする

- 日付: 2026-10-12
- 状態: 採用。有限campaignと再現試験を実行して記録する

利用者は686問の小規模評価を不十分とし、入力者が躓く点を万単位で見つけるよう指示した。AGENTSの「精度は十分」という以前の前提を改める。Standard AJIMEE90%以上の既存の基準は維持する。

ランダムかなや同じ文章の操作違いで文章数を増やす方法を採らず、固定した上流自然文読み・既報回帰・姓・既存調整セット・実務テンプレートから重複のない読みを作り、実辞書/実モデルのNative SessionHandlerへ打鍵と変換を送る。生成器は13,178種類を出力した。意味/期待表記の条件があるのは2,910件だけであり、残りから意味の正解率を捏造しない。

Windows TSFを1万回UI操作する方法はアプリ/OS要因まで見られるが、独立したデータ採取と再現には時間がかかる。まず隔離Native SessionHandlerで探索し、キー欠落、誤補正、候補選択、待ち時間を抽出する。実TSFの受入れ検証は別に残す。既存のheldoutは開発探索へ使わない。

厳密な表記不一致はレビュー待ちであり、意味の誤りと同一視しない。人名候補の未観測も辞書の欠落と同一視しない。初回/即Spaceの探索を完走した後、通常速度・待機・AI ON/OFF・候補展開で再現し、CPUのみの代表例も実行する。原票と失敗した試行は保持する。

検査器自体にも欠測、重複、変更された期待値、文字コード例外のテストを設ける。再試験で架空の確定イベントを作らず、Enterを送らない試験には確定未検査の印を付ける。データ/モデル/バイナリをコミットせず、抽出コード、原典SHA、検査記録を残す。

具体的なコマンドと判定範囲は `docs/LARGE_INPUT_CAMPAIGN.md`、最終実行結果は `docs/verification/large-input-campaign-20261012.md` に記録する。数値が改善したという主張は、実際の前後比較が取れた変更だけに限定する。

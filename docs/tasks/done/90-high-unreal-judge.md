# 90: High・Unreal の判定役(大きな LLM)

- 依頼: 利用者(2026-11-03)「大きなモデル high unreal のシステムを導入」
- 前提: docs/adr/0086(段階と追加の AI のダウンロード)、カード 89(一貫性)

## 背景
5.0.0 では、High・Unreal は「採点の LLM を大きな LLM に替える」作りだった。Qwen3-4B・Qwen3-8B・sarashina2.2-3b の
どれも Standard(TinySwallow-1.5B)を下回った(文脈の選択 297 問で 236 → 216〜221。docs/verification/v5-models-20261103.md)。
利用者の見立て(2026-11-03): TinySwallow は十分に強く、問題は仕組み(文脈の読み方・採点の合わせ方)にある。
zenz(genmai)を外すと正解率が下がった過去の記録もある。

## 作り
- Standard の採点(genmai + TinySwallow)はそのまま。大きな LLM は **判定役** にする。
- 1 番目との点差が `judge_margin_` 以内の上位 `judge_top_` 件(既定 4)だけを、大きな LLM で採点し直し、
  `judge_weight_` 倍を足して 1 番目を選び直す。点差が大きい(Standard が確信している)文は変えない。
- 開発では `KOTORI_LM_JUDGE`(ファイル)・`_MARGIN`・`_WEIGHT`・`_TOP` で試す。製品では、設定画面から受け取った
  追加の AI(表 `kotori_model_catalog`)を判定役にする。Eco・GPU のない PC・使わなくなったときは GPU から下ろす。

## 採否の基準
- 開発用(文脈の選択 297・文章 232・日常 81)で Standard より明らかに良い(下がるセットがない)。
- 判定用(普段使い 120・文脈の選択 297・文章 233。調整に使わない)でも下がらず、どれかで上がる。
- Space→候補の p95 の増え方を記録する(利用者は精度を優先。固まらないこと)。
- 満たさなければ表は空のまま(判定役の仕組みだけ入れる)。

## 結果
Llama-3.1-Swallow-8B-v0.5 Q4_K_M を、意味の選び分けだけの判定役(重み 2.0・点差 3・上位 4)として Unreal に載せた。
開発用の文脈の選択 235 → 238、日常 78 → 81、判定用の文脈の選択 225 → 228、下がったセットなし。利用者の承認(2026-11-04)で
aruiki/Llama-3.1-Swallow-8B-v0.5-GGUF@a6258e14 に元の規約の文面と一緒に置いた。High は同じモデルの Q3_K_M(判定用 225 → 229、
同じ場所の @a96b0217)。

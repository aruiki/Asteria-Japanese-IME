# 84: 入力モードを分かりやすくする(半角英数モードの整理とアプリ間の共有)

- 仕様: SPEC の入力モード(TSF の開閉と変換モード)
- 前提: なし
- 規模の目安: TIP とセッションで数百行

## 目的
利用者の指摘(2026-10-24)。(1)「A」に下線の付いた半角英数モード(IME オンのまま英字を未確定で入力する Mozc 由来のモード)に
意図せず入り、Enter を押すまで英字が確定しない、ショートカットが効かない、などの不満が多い。英字を打つなら直接入力で足り、
独立したモードとしての必要性は薄い。(2) アプリ(窓)を切り替えると入力モードがリセットされる。TIP が開閉状態と変換モードを
スレッドごとの compartment(`GUID_COMPARTMENT_KEYBOARD_OPENCLOSE`、`..._INPUTMODE_CONVERSION`)に持つため。

## 読むもの
- `win32/tip/tip_status.cc`、`win32/tip/tip_text_service.cc`(compartment の読み書き、窓の切り替え)
- `session/session.cc` の HALF_ASCII への切り替え(英数キー、Shift、自動英数変換 `use_auto_ime_turn_off` など)
- 設定画面の「シフトキーでの入力切替」「自動英数変換を有効にする」

## 手順
1. 半角英数モードに入る経路を洗い出し、実機(メモ帳・Edge・VS Code・Office)で起きる不具合を再現して記録する。
2. 英数キー・モード切り替えでは直接入力(IME オフ)にし、未確定の英字を作らない。日本語の途中に英字を混ぜる Shift＋英字は
   未確定の中で扱う(確定すれば日本語モードに戻る)。
3. 最後に使ったモード(オン/オフと、ひらがな/カタカナ等)を全アプリで共有する設定を加え、既定で有効にする。新しい窓・
   切り替えた窓では、その値を compartment に書く。
4. 変更を ADR に記録する。

## テスト
- セッション: 英数キーで直接入力になる、Shift＋英字の後に確定すると日本語に戻る。
- TIP: 窓 A でひらがな → 窓 B に切り替えてもひらがな(共有が有効なとき)。実機の受入れ試験に項目を足す。

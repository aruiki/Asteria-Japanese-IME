# 作業カード

1枚のカードで1つの目的を追跡する。利用者の現在の依頼と HANDOFF を優先し、それ以外は未着手のカードを番号順に進める。既存カードの修正・再検証では新しいカードを増やさない。
終わったカードは `done/` に移す。進め方は `AGENTS.md`。コマンドは `docs/DEVELOPMENT.md` の「1. Mozc 版」。結果の詳細は verification にまとめ、カードには完了条件と参照を残す。

## カードの形

カードは目的・関連REQ・完了条件・PRまたは検証記録への参照を基本にする。読むもの・手順・テスト・注意は必要な場合だけ追加する。詳細な結果を再掲しない。以下は記入例。

```markdown
# NN: 題(一行)

- 仕様: SPEC の節と REQ ID
- 前提: 先に終わっているべきカード(なければ「なし」)
- 規模の目安: 差分の行数

## 目的
何ができるようになるか。2〜3 行。

## 読むもの
変更の前に読むファイルと節。

## 手順
1. 具体的に(ファイル名・関数名・型名を書く)。

## テスト
追加するテストの名前と、確かめること。

## 完了条件
- [ ] 確かめ方(`AGENTS.md`)の数値を PR に貼り、CI が緑
- [ ] ほかの具体的な条件

## 注意
はまりどころ。
```
